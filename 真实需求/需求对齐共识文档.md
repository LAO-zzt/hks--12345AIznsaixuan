## 0. 一句话结论（先对齐这个）

客户（顺德区政数局）要的**不是**一个"预警处置系统"，而是一个能**批量、准确**把"不同市民投诉同一件事/同一主体"的工单挑出来、用**表格**呈现、能**演示**的 AI 工作流，目标是**提效**。

## 2. 问题定义（我们到底要解决什么）

### 2.1 现状痛点

- 工单海量（日均 1800+），诉求人表述不一。
- 现有方式：人工记录 + 关键词精确匹配搜索 → 漏检严重、效率低。

### 2.2 核心难题 = 语义识别（研讨会点名的"最难也最该做对"的环节）

- 同一件事，不同人用不同表述 / 简称 / 全称 → 关键词精确匹配会漏。
- 例：公司全称 vs 简称；简称 A 与另一公司 B 名字极像但含义完全不同。
- 研讨会明确：**"大模型也解决不了语义识别"**。可靠手段是**规则归一**（同义词、简称↔全称、主体别名、关键词扩展到 50–100 个相近词再锁定）+ 相似度 + （可选）LLM 判重。

### 2.3 明确边界（防止再过度建设）

客户**只要求**：多频识别（提效）+ 表格呈现 + 可演示。  
客户**没要求、评分没勾**：风险预警、趋势预测、空间分析、处置建议、客服话术、整改方案。  
→ 后者一律定为"可选扩展 / 演示糖衣"，**不挡主线**。

## 3. 业务流程（端到端，研讨会框架落地）

```
① 数据接入    CSV/xlsx 上传（或内置样例）→ 解析、时间从工单号 YYMMDD 提取
      ↓
② 清洗去重    剔除"同一人重复提交"的完全相同的工单（避免重复计数）
      ↓
③ 语义归一    【核心】同义词 / 简称↔全称 / 主体别名 / 关键词扩展 → 把"指同一事"的文本对齐
      ↓
④ 相似度+判重  TF-IDF+余弦 算相似度；达阈值(约60–70%)的候选对，可选送 LLM 推理是否同一事件
      ↓
⑤ 多频识别     按"同一主体"和"同一事件"两条轴归类 → 标记多频工单、统计频次
      ↓
⑥ 表格输出    【最低成果】导出 CSV/Excel + 看板，呈现多频工单清单与归集关系
      ↓
⑦ (可选)推送   飞书 Webhook 推送 Top 高关注多频事件 —— 给"落地潜力"加分，轻量实现
```

> 归类两条轴（研讨会明确）：**按实体/主体归类**、**按事件归类**。多频定义本身就含"同一事件"与"同一主体"两个维度。

## 5. 测试与评测计划（研讨会强调的"最关键点"）

> 原话："你自己得有指标…你不能指望客户去一个一个验证。"

### 5.1 必须有标注测试集

- 从真实样例数据（2025年1–3月顺德12345工单）中**人工标注**一批"多频工单对"：哪些工单属于同一事件/同一主体。
- 标注方法：用规则告诉系统"这两个东西是一个东西"（研讨会实战做法）。
- 规模：覆盖 5+ 类高频场景（参考现有 sample.csv 的 5 类），不少于 50–100 条成对标注。

### 5.2 评测指标（对应"完成度"的硬证据）

- **多频识别准确率 / 召回率 / F1**：系统判出的多频归集 vs 人工标注的吻合度。
- **判重一致性**：候选对判重结果 vs 标注。
- **覆盖率 / 碎片化率**：聚类质量（现有可靠性设计已含，补成量化报告）。

### 5.3 验收门槛（已拍板）

- 多频识别 **F1 ≥ 0.85** 作为基线（团队认可，具体数值可微调）；语义归一规则补齐后方算主线达标。
- 达不到时，定位是"规则漏"还是"聚类碎"，针对性补词典 / 调阈值。
- **当前阶段首要目标 = 提升召回率**：LLM 判重与 embedding 增强均**常开**，先把"能捞出的真实多频对"覆盖面做上来；"匹配几率有多高"即现阶段评测核心指标，准确率由语义规则归一 + LLM 兜底。

> 📌 **关键约束变更**：8/14 定的"离线不付费"约束，经本次对齐**已放宽**——LLM（DeepSeek API）与 embedding 增强均常开，目标为最大化召回。联网/成本由 API Key 与本地 embedding 模型承载，不再追求纯离线。

## 6. 我们已经跑偏的点（复盘，团队引以为戒）

1. **过度建设预警处置体系**：风险评分、趋势、空间、预警大屏、地图——客户没要求、评分没勾，却占了主线精力。
2. **缺评测闭环**：测试只有 smoke/ui/容错（11 项），**没有标注集量"识别准不准"**，而这是评分"完成度"最直接的证据。
3. **架构以通用 DBSCAN 聚类为骨架**，未必精准服务"这两张工单是不是同一件事"的判重本质；应让**语义规则归一**当主干。

### 2026-08-24 评测闭环结论（zzt 侧完成）

- **金标准标注集**：`tests/eval/gold_set.csv`（36 对，覆盖 拖欠工资/劳动纠纷、噪音、消费/网购纠纷、占道经营、环境卫生、失业保险金 8 类；正 4 / 负 32）。
- **评测脚本**：`tests/eval/eval_multi_freq.py`（成对判重：同一簇=同一事件，输出 P/R/F1 与判错定位）。
- **基线**（旧路线 标题分组+「事件+区域」签名归并）：F1=0.211（P=0.125/R=0.667），28/30 误并源于把不同主体/场所并入巨簇。
- **修复**（`modules/cluster.py` 大数据路线 + textclean 抽取 + 词典）：
  1. 分组键改为 **归一事件 + 主体键**（具体主体→场所专名→含地标地址→镇街；系统性事件如失业保险金按事件归并）；
  2. textclean 增加**劳动/欠薪场景公司抽取**（名称/被X公司拖欠/在X工作/项目单位等），治"同镇不同公司被并"；
  3. **场所专名提取**（高黎市场→同一主体）+ synonyms 扩充（拖欠工资问题/拖欠薪资/克扣工资/劳动纠纷问题→拖欠工资；失业保险金问题→失业保险金；中电建九局→中电建等）。
- **调优后**：**F1=1.000**（TP=4/FP=0/FN=0/TN=32），聚类粒度 25547→107752（巨簇消失），多频簇 966→2738。

### 2026-08-24 规模一致性修复（重要）

- **问题**：旧路由按 `CLUSTER_MAX_ROWS=15000` 切算法——>1.5 万走分组路线、≤1.5 万走 DBSCAN。实测 **2 万条 F1=1.000（正常）**，但 **1 万条切到 DBSCAN 后 F1 暴跌到 0.222**（12 个误并）。真实使用/演示若按 2 万里抽一部分、按月分片或只给几千条，判重会崩回基线。
- **修复**（`modules/cluster.py`）：**统一判重路线**——任意规模都走「归一事件+主体键」分组（O(n) 线性，12.8 万条约 4s，精度已验证一致）；DBSCAN 仅保留为「无标题且无事件类型」数据的兜底；`_bigdata_labels` 增加标题缺失时用事件类型兜底。
- **修复后全规模验证**：**12.8 万 / 2 万 / 1 万 三档 F1 均 = 1.000**，规模不再影响判重质量。
